## Prerequisites

Before you begin, make sure you have:

- Node.js 22.12.0 or higher installed
- At least one ACP-compatible agent installed (Codex, Claude, Pi, or OpenClaw)

If you haven't installed acpx yet, see the [Installation Guide](/installation).

## Step 1: Install acpx

<CodeGroup>
```bash npm
npm install -g acpx@latest
```

```bash npx
npx acpx@latest --help
```
</CodeGroup>

## Step 2: Create Your First Session

Sessions in acpx are persistent, multi-turn conversations scoped to your project directory. Create a session for your current project:

```bash
acpx codex sessions new
```

<Info>
  If you don't have Codex installed, replace `codex` with your preferred agent: `pi`, `openclaw`, `claude`, etc.
</Info>

You should see output confirming the session was created:

```
Session created
  sessionId: abc123...
  agentCommand: codex
  directory: /path/to/your/project
```

## Step 3: Send Your First Prompt

Now send a prompt to your agent:

```bash
acpx codex "summarize what this project does"
```

You'll see structured output showing the agent's thinking and tool usage:

```
[thinking] Analyzing project structure and files

[tool] List directory contents (completed)
  output:
    src/
    package.json
    README.md
    ...

[thinking] Based on the package.json and README...

This is a [description of your project]

[done] end_turn
```

## Step 4: Continue the Conversation

Since sessions are persistent, you can send follow-up prompts without losing context:

```bash
acpx codex "what are the main dependencies?"
```

The agent remembers the previous conversation and can build on that context.

## Step 5: Inspect Your Session

View session metadata:

```bash
acpx codex sessions show
```

View conversation history:

```bash
acpx codex sessions history --limit 5
```

## Common Workflows

### One-Shot Execution (No Session)

For quick, stateless tasks, use `exec`:

```bash
acpx codex exec "count the number of TypeScript files in src/"
```

This runs without creating or using a persistent session.

### Named Sessions for Parallel Work

Create multiple named sessions to work on different tasks in the same project:

```bash
# Create a session for backend work
acpx codex sessions new --name backend
acpx codex -s backend "review the API endpoints"

# Create a session for frontend work  
acpx codex sessions new --name frontend
acpx codex -s frontend "update the UI components"
```

### Prompt from File or Stdin

Read prompt content from a file:

```bash
acpx codex --file prompt.md
```

Read from stdin:

```bash
echo "explain the auth flow" | acpx codex
```

### Output in JSON Format

For automation and scripting, use JSON output:

```bash
acpx --format json codex exec "list all TODO comments" | jq -r '.message'
```

## Permission Modes

By default, acpx uses `--approve-reads` mode, which auto-approves file reads and searches but prompts for writes.

<Tabs>
  <Tab title="Approve Reads (Default)">
    Auto-approve reads, prompt for writes:
    ```bash
    acpx codex "review the codebase"
    ```
  </Tab>

  <Tab title="Approve All">
    Auto-approve all permissions (for automation):
    ```bash
    acpx --approve-all codex "fix the tests and commit"
    ```
  </Tab>

  <Tab title="Deny All">
    Deny all tool access (explanation-only mode):
    ```bash
    acpx --deny-all codex "explain how sessions work"
    ```
  </Tab>
</Tabs>

## Session Management

<Steps>
  <Step title="List all sessions">
    ```bash
    acpx codex sessions list
    ```
  </Step>

  <Step title="Check session status">
    ```bash
    acpx codex status
    ```
    Shows if the session process is running, dead, or doesn't exist.
  </Step>

  <Step title="Close a session">
    ```bash
    acpx codex sessions close
    ```
    Soft-closes the session (keeps history, stops processes).
  </Step>
</Steps>

## Configuration

View your resolved configuration (global + project):

```bash
acpx config show
```

Initialize a global config file:

```bash
acpx config init
```

This creates `~/.acpx/cli/config.json` where you can set defaults:

```json
{
  "defaultAgent": "codex",
  "defaultPermissions": "approve-all",
  "ttl": 300,
  "format": "text"
}
```

See the [Configuration Guide](/guides/configuration) for all options.

## Advanced Features

### Prompt Queueing

If you submit a prompt while one is already running, it gets queued:

```bash
# First prompt starts running
acpx codex "refactor the auth module"

# Second prompt queues automatically
acpx codex "update the tests"
```

### Fire-and-Forget

Queue a prompt and return immediately:

```bash
acpx codex --no-wait "generate documentation"
```

### Cooperative Cancellation

Cancel an in-flight prompt gracefully:

```bash
acpx codex cancel
```

Or press `Ctrl+C` during a running prompt to send an ACP `session/cancel` request.

### Session Controls

Change session mode:

```bash
acpx codex set-mode careful
```

Set configuration options:

```bash
acpx codex set reasoning_effort high
```

## Practical Example

Here's a complete workflow reviewing and fixing a failing test:

```bash
# Create a session for test work
acpx codex sessions new --name tests

# Ask the agent to identify the failing test
acpx codex -s tests "run the tests and identify any failures"

# Ask for a fix
acpx codex -s tests "fix the failing checkout test"

# Verify the fix
acpx codex -s tests "run the checkout test again to verify"

# View the conversation history
acpx codex sessions history -s tests --limit 10

# Close the session when done
acpx codex sessions close tests
```
