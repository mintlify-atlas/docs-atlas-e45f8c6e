## Overview

The `status` command shows the local process status for a cwd-scoped session. It reports whether the queue owner process is running, dead, or no session exists, along with metadata like pid, uptime, and last prompt time.

## Syntax

```bash
acpx [global_options] <agent> status
acpx [global_options] <agent> status -s <name>
acpx [global_options] status
acpx [global_options] status -s <name>
```

## Behavior

- Checks for a session matching `(agentCommand, cwd, name?)`
- If no session exists, reports `no-session`
- If session exists, probes queue owner health using PID-based check (`kill(pid, 0)` semantics)
- Reports `running` if queue owner is healthy
- Reports `dead` if queue owner is not running
- Status checks are local and do not communicate with the agent

<Note>
Status checks are PID-based and local. They do not send ACP messages or interact with the agent process.
</Note>

## Options

<ParamField path="-s, --session" type="string">
  Use named session instead of cwd default.
</ParamField>

## Status Values

| Status | Meaning |
|--------|-------|
| `no-session` | No session record exists for the scope |
| `running` | Queue owner process is healthy and running |
| `dead` | Session exists but queue owner is not running |

<ParamField path="session" type="string">
  acpx record id for the session.

<ParamField path="uptime" type="string">

</ParamField>

</ParamField>

<ParamField path="signal" type="string">

</ParamField>

## Examples

### Basic Usage

```bash
# Check default session
acpx codex status

# Check named session
acpx codex status -s backend

# Different agent
acpx pi status
```

### While Prompt is Running

```bash
# Terminal 1: send long-running prompt
acpx codex "run full test suite and report failures"

# Terminal 2: check status
acpx codex status
# Output:
# session: abc123
# pid: 12345
# status: running
# uptime: 00:02:15
# lastPromptTime: 2026-03-14T10:30:00Z
```

### After Session Crash

```bash
# Session crashed or was killed
acpx codex status
# Output:
# session: abc123
# status: dead
# exitCode: 1

# Next prompt auto-recovers
acpx codex "continue where we left off"
# Session automatically respawns and resumes
```

### No Session

```bash
# Before creating session
acpx codex status
# Output:
# status: no-session

# Create session
acpx codex sessions new

# Check again
acpx codex status
# Output:
# status: running
```

### JSON Automation

```bash
# Check if session is running
STATUS=$(acpx --format json codex status | jq -r '.status')

if [ "$STATUS" = "alive" ]; then
  echo "Session is healthy"
else
  echo "Session is not running"
  acpx codex sessions ensure
fi
```

### Monitoring Script

```bash
#!/bin/bash
# Monitor session health

while true; do
  STATUS=$(acpx --format quiet codex status)
  echo "[$(date)] Status: $STATUS"
  
  if [ "$STATUS" = "dead" ]; then
    echo "Session died, restarting..."
    acpx codex sessions ensure
  fi
  
  sleep 60
done
```

## Queue Owner Health

The status command checks queue owner health, not the underlying agent process. The queue owner is a long-running acpx process that:

- Manages prompt queueing for the session
- Keeps the agent connection alive
- Drains queued prompts sequentially
- Shuts down after idle TTL expires

When `status` reports `running`, it means the queue owner is healthy and can accept prompts. When `dead`, the next prompt will spawn a new queue owner and attempt to resume the session.

## Auto-Recovery

If status shows `dead`, the next `prompt` command will automatically:

1. Respawn the agent
2. Attempt `session/load` with the stored session id
3. Fall back to `session/new` if loading fails
4. Continue accepting prompts

No manual intervention is required for recovery.

## Status vs Sessions Show

| Command | Purpose |
|---------|-------|
| `status` | Check if queue owner is running (process health) |
| `sessions show` | Show full session metadata (record details) |

Use `status` for runtime health checks. Use `sessions show` for detailed session inspection.
